02Transaction Firewall

Stop malicious transactions before execution.

Pre-execution transaction security. The firewall is designed to analyze instructions, simulated asset movements, program interactions, recipients, permissions and known threats, and to stop unauthorized or suspicious execution.

  • Authorized protocols
  • Authorized wallet addresses
  • Restricted programs
  • Unauthorized transfer prevention
  • Transaction simulation requirements
  • Permission change restrictions
  • Human approval thresholds
  • Emergency execution suspension

An API key alone is not enforcement. If an agent holds an unrestricted private key, it can send transactions onchain without asking Intercept. In Evaluation mode, Intercept returns a decision and the agent is expected to respect it. Enforced Execution mode routes signing through a restricted signing environment, delegated permissions or a compatible smart account, so a blocked transaction cannot be executed. It is in development and will be validated through security research.

Live decoding and simulating the real serialized transaction, program, recipient and token allow and block lists, delegate approvals, authority changes, unknown instructions and unexplained outflows.In development more protocol decoders and Token-2022 extensions.

          Architecture

          Security embedded into the execution layer.

          The backend is the source of truth: every request is authenticated, evaluated against the latest version of the agent’s policy and recorded. The frontend never enforces security rules. The agent proposes, Intercept decides, and the integrated execution environment enforces the decision.

          Transaction lifecycle

          1. The agent generates a proposed transaction.
          2. It submits the transaction through the Intercept API.
          3. Intercept authenticates the agent from its API key.
          4. It retrieves the agent’s active policy version.
          5. The transaction is decoded and simulated. In development
          6. The Risk Engine evaluates its financial impact.
          7. The Transaction Firewall evaluates its security implications.
          8. The Policy Engine checks compliance with the configured rules.
          9. Intercept returns an authorization decision.
          10. The integrated execution environment enforces it. Enforced mode in development
          11. The evaluation is recorded in the agent’s history.

          APPROVEDBLOCKEDREQUIRES_APPROVAL, each with an explanation, the triggered policies, risk details and an evaluation ID.

          Integration modes

          Evaluation mode Live

          The agent calls the API inside its existing workflow and receives decisions, risk analysis and monitoring. It relies on the agent respecting the decision.

          Enforced Execution mode Live · v1

          The signer only signs with a signed, single-use Intercept authorization bound to the exact transaction. Agents cannot bypass their policies as long as the signing key stays behind that check. A hosted signer and on-chain enforcement are in development.

          An API key identifies the agent. It does not, on its own, stop an agent that holds an unrestricted private key.

          Developers

          Built for developers. Designed for autonomy.

          Integrate Intercept where your agent creates transactions, whatever model or framework it runs on. Trading agents, portfolio managers, DeFi agents and automated payment systems all follow the same workflow.

          1. Create an agent in the dashboard.
          2. Configure its policies.
          3. Generate its API key and store it as a secret.
          4. Install the integration. REST today; SDKs and MCP in development.
          5. Submit transactions for evaluation before execution.
          6. Receive the decision and its reasons.
          7. Execute through the configured signing environment.

          What is available. In preview: the REST evaluation endpoint with per-agent API keys, evaluating the parameters your agent declares. Not yet released: TypeScript and Python SDKs, MCP and agent framework integrations, transaction decoding and simulation, Enforced Execution mode. The SDK example is illustrative.

          import { Intercept } from "@intercept/sdk"; // illustrative, not published

const intercept = new Intercept({
  apiKey: process.env.INTERCEPT_API_KEY, // identifies the agent
});

export async function execute(tx: Transaction) {
  const decision = await intercept.evaluate({ transaction: tx });

  switch (decision.status) {
    case "approved":
      return signAndSend(tx);
    case "requires_approval":
      return queueForOwner(tx, decision.reasons);
    case "blocked":
      throw new Error(decision.reasons[0].code); // e.g. RISK_MAX_LEVERAGE
  }
}
